# ViewCast security audit findings

Date: 2026-07-29

## Scope

- Static HTML/CSS and browser JavaScript
- Firebase Authentication flows
- Firestore Standard edition, native mode, database `(default)` in `nam5`
- Callable Cloud Function `generateGeminiContent`
- YouTube OAuth token handling and Google API requests
- Firebase Hosting policy and browser security headers

## Firestore access model

- Collection: `users`
- Document: `users/{firebaseAuthUid}`
- Reads: direct owner document reads only
- Creates/updates: owner document writes only
- Deletes: owner document deletes only
- Queries: none (`where`, `orderBy`, collection reads, and list queries are not used)
- PII: email and creator account data remain in the owner-only document

## Data model

- Required user fields: `uid`, `email`, `displayName`, `updatedAt`, `lastSignInAt`
- Optional immutable field: `createdAt`
- Optional context: `channelTopic`, `channelContext`
- Optional YouTube connections: at most 10 strictly validated connection maps
- Connection maps contain a validated channel map, optional validated analytics
  map, and a positive connection timestamp

## Findings and fixes

1. High: a local-storage value for the plan name entered an `innerHTML`
   template. Fixed by assigning it through `textContent`.
2. High: YouTube channel IDs/titles entered `<option>` markup through
   `innerHTML`. Fixed with DOM element creation and `textContent`.
3. High: the client supported direct Gemini API keys in browser storage.
   Removed; Gemini is callable only through the authenticated Firebase
   Function and Secret Manager.
4. High: the Gemini callable accepted effectively unbounded request/config
   payloads. Added strict message, text, image, MIME type, output-token, model,
   and generation-config validation plus basic per-instance rate limiting.
5. Moderate: YouTube OAuth bearer tokens were persisted in `localStorage`.
   Moved to tab-scoped `sessionStorage` and legacy persistent tokens are
   deleted.
6. Moderate: Firebase Hosting had no explicit browser security policy. Added
   CSP, clickjacking protection, MIME sniffing protection, a referrer policy,
   a permissions policy, and popup-compatible opener isolation.
7. Moderate: Firestore validated connection list size but not nested contents.
   Added strict nested schemas, types, URL constraints, string bounds, numeric
   bounds, and a 10-item maximum.
8. Moderate: creator analytics and channel caches could survive sign-out on a
   shared browser. Added centralized sign-out cleanup for OAuth credentials,
   connection metadata, analytics, AI analysis, and channel-context caches.
9. Moderate: the root and Functions dependency trees contained known
   vulnerabilities. Updated the affected dependency chains and lockfiles;
   both production dependency audits now report zero known vulnerabilities.

## Devil's advocate checks

- Public list exploit: denied; no public rule and no list rule exists.
- Cross-user read/write/delete: denied by UID path ownership.
- Update bypass/schema pollution: denied by `isValidUser` on create and update
  plus `hasOnly`.
- Ownership hijacking: denied by path UID and immutable UID checks.
- `createdAt` modification: denied when the existing field is present.
- Type juggling: denied for all top-level and connection fields.
- Resource exhaustion: top-level strings and lists are bounded; nested
  connection strings and list elements are now bounded and validated.
- Required-field omission: denied by `hasAll`.
- Privilege escalation: no role or permission fields are accepted.
- Timestamp manipulation: `updatedAt` must equal `request.time`; `createdAt`
  remains immutable after creation.
- Mixed-content leak: denied because user documents are owner-readable only.
- Orphaned subcollections: denied by default because no subcollection match
  grants access.
- Query mismatch: the application performs direct owner document reads only.

## Residual considerations

- In-memory Cloud Function rate limiting is a cost-control layer, not a global
  distributed quota. Firebase App Check and a durable server-side quota should
  be enabled before high-volume public launch.
- CSP currently permits inline styles because the existing site uses style
  attributes. Removing those attributes would allow a stricter style policy.
- Security rules and headers must be deployed before they protect production.
- Firestore point-in-time recovery and delete protection are currently
  disabled. Enabling either changes the project's billing/operational posture,
  so that decision remains with the project owner.
